**Дата:** 27.11.2025

**Тема:** Основы системы контроля версий Git. «Спасательная машина времени для кода».

**Цель:** Сформировать у обучающихся понимание философии и базовых навыков работы с системой контроля версий Git для управления исходным кодом веб-проектов.

**Задачи:**
1.  **Образовательная:** Объяснить необходимость использования VCS. Научить основам работы с Git: инициализация репозитория, фиксация изменений (commit), просмотр истории.
2.  **Развивающая:** Развивать алгоритмическое мышление и навыки последовательной работы. Развивать понимание процессов командной разработки.
3.  **Воспитательная:** Воспитывать культуру аккуратного и организованного ведения проекта, привычку к регулярному сохранению рабочих результатов.

**Форма занятия:** Комбинированная (фронтальное объяснение → практическая работа в парах/индивидуально).

**Оборудование:**
*   Для педагога: Компьютер, проектор, аккаунт на GitHub/GitLab для демонстрации.
*   Для обучающихся: Компьютеры с установленными **Git** и **VSCode** (или другим редактором с интегрированным терминалом). Аккаунты на **GitHub** (желательно создать заранее).
*   Раздаточный материал: Шпаргалка с основными командами Git, схема жизненного цикла файлов.

### **План занятия:**

1.  **Организационная часть (3 мин):** Приветствие, проверка готовности (установлен ли Git), объявление темы.
2.  **Актуализация опорных знаний. Мотивация (10 мин):** Проблемная ситуация: «Как откатиться к рабочей версии после неудачных изменений?», «Как работать над одним проектом в команде?» Анализ «варварских» методов (копирование папок, файлы final_final_2.html).
3.  **Освоение нового материала (20 мин):**
    *   Что такое Git и система контроля версий (VCS). Аналогия с «машиной времени» и «контрольными точками» в играх.
    *   Базовые понятия: **репозиторий**, **коммит**, **хэш**, **ветка** (как «альтернативная реальность»).
    *   Жизненный цикл файла в Git: **рабочая папка → staging area (индекс) → репозиторий**.

4.  **Закрепление новой темы. Практикум (45 мин):** Создание и ведение локального репозитория.

    *   **ДЗ:** 1) Создать локальный репозиторий для своего учебного проекта. 2) Сделать 3 содержательных коммита с изменениями в коде. 3) Прислать скриншот истории (`git log --oneline`).

### **Ход занятия:**

#### **1. Орг.часть (3 мин)**
«Здравствуйте! Сегодня мы начнем изучать инструмент, который кардинально изменит ваш подход к разработке и без которого немыслима профессиональная работа — систему контроля версий Git. Проверим, у всех ли установлен Git (`git --version` в терминале). Отлично, поехали!»

#### **2. Теоретическая часть (30 мин = 10 мин мотивация + 20 мин новый материал)**
*   **Мотивация (проблемный подход):**
    «Представьте: вы три часа верстали сайт, все было идеально. Потом решили «улучшить» меню и все сломалось. Как вернуть рабочую версию? Копировать папку `project_backup_5`? А если над проектом работаете вы с другом? Как объединить ваши правки? Git создан, чтобы решить эти проблемы раз и навсегда».
*   **Объяснение нового материала с демонстрацией в терминале:**
    1.  **Концепция:** Git — это распределенная система, которая хранит не файлы, а **снимки (снапшоты)** их состояний. Показываем схему: рабочая директория → индекс (staging area) → репозиторий (.git folder).
    2.  **Базовые команды (демонстрация на простом примере):**
        *   `git init` – «Инициализируй здесь «машину времени».
        *   `git status` – «Что происходит?» (главная команда для новичка).
        *   `git add .` или `git add index.html` – «Подготовь эти файлы к сохранению в историю».
        *   `git commit -m "..."` – «Сохрани снимок с пояснением». Акцент на **качественных сообщениях**.
        *   `git log --oneline` – «Покажи историю сохранений».

#### **3. Практическая часть (45 мин)**
«Теперь ваша очередь пройти весь путь от пустой папки до репозитория с историей. Следуйте инструкции».

**Пошаговая инструкция для учащихся:**

1.  **Настройка «паспорта»:**
    ```bash
    git config --global user.name "Ваше Имя"
    git config --global user.email "ваша-почта@example.com"
    ```

2.  **Создаем проект:**
    ```bash
    mkdir my-first-git-project
    cd my-first-git-project
    git init
    ```
    *(Посмотрите на скрытую папку .git)*

3.  **Первый коммит:**
    *   Создайте файл `index.html` с базовой структурой HTML.
    *   Выполните:
    ```bash
    git status # Увидите новый неотслеживаемый файл
    git add .  # Добавили ВСЕ новые файлы в индекс
    git status # Увидите, что файлы готовы к коммиту
    git commit -m "Initial commit: создана базовая HTML-структура"
    git log --oneline # Увидите ваш первый коммит!
    ```

4.  **Вносим изменения и фиксируем их:**
    *   Добавьте в `index.html` заголовок `<h1>Мой первый проект с Git</h1>`.
    *   Создайте файл `style.css` с одним правилом.
    *   Выполните:
    ```bash
    git status
    git add . # или git add index.html style.css
    git commit -m "Добавлены заголовок и базовые стили"
    git log --oneline # Теперь в истории 2 коммита
    ```

5.  **Исследуем (опционально):**
    ```bash
    git diff HEAD~1 # Покажет, что изменилось с прошлого коммита
    ```

*Педагог контролирует процесс, помогает с ошибками, проверяет сообщения коммитов.*

#### **4. Рефлексия (5 мин)**
«Давайте сделаем паузу и обсудим.
*   Кому концепция «индекс / staging area» показалась неочевидной? Зачем она нужна?
*   Какие сообщения коммитов вы писали? «Правка 1» или «Исправлено выпадание меню на мобильных»?
*   Почувствовали ли вы уже, как Git снимает тревогу «а вдруг я все сломаю»?»

#### **5. Подведение итогов занятия (7 мин)**
«Сегодня вы сделали самый важный шаг — начали использовать Git локально. Вы научились создавать контрольные точки (коммиты) вашего проекта. Это фундамент. Запомните простой алгоритм дня: **изменил → `git add` → `git commit`**.
На следующем занятии мы выведем ваш репозиторий в «облако» — на GitHub, чтобы показать миру и научиться работать вместе.
**Домашнее задание:** Применить этот алгоритм к вашему реальному учебному проекту. Сделать 3 осмысленных коммита. Прислать скриншот `git log`.
Спасибо за работу! Ваш код теперь под защитой».
