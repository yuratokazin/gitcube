## как определить Wi-Fi адаптер в Debian

Чтобы определить наличие и состояние Wi-Fi адаптера в Debian, используйте следующие команды в терминале:

\1. Определение оборудования

Для начала нужно понять, видит ли система саму сетевую карту:

- **Для PCI-устройств (встроенные адаптеры):**
  `lspci | grep -i network` или `lspci -nn | grep Network`. Это покажет модель чипа и его ID (например, `[8086:0085]`), что важно для поиска драйверов.
- **Для USB-адаптеров:**
  `lsusb`. Ищите строки, содержащие "Wireless" или названия брендов (Realtek, Atheros, Broadcom). 

\2. Проверка сетевого интерфейса

Если драйвер установлен, устройство должно появиться в списке интерфейсов:

- `ip link show` — ищите интерфейс, начинающийся на **w** (например, `wlan0` или `wlp2s0`).
- `iwconfig` — классическая команда для проверки параметров беспроводной связи. Если она выдает "no wireless extensions", значит интерфейс не является  беспроводным или драйвер не загружен. 

\3. Поиск доступных сетей

Если интерфейс активен, можно просканировать эфир:

- **С помощью nmcli (если установлен NetworkManager):**
  `nmcli dev wifi list` — выведет список всех доступных точек доступа, их уровень сигнала и тип шифрования.
- **С помощью iwlist (требует пакет wireless-tools):**
  `sudo iwlist scan` или `sudo iwlist wlan0 scan`. 

\4. Проверка состояния подключения

- `ip addr show wlan0` — покажет, получен ли IP-адрес.
- `cat /proc/net/wireless` — выведет техническую информацию о качестве сигнала и уровне шума. 

**Что делать, если адаптер не виден?**
В Debian часто отсутствуют "несвободные" (non-free) прошивки по умолчанию. Если `lspci` видит карту, но интерфейс `wlan0` не появляется, скорее всего, нужно установить пакеты прошивок (например, `firmware-iwlwifi`, `firmware-realtek` или `firmware-atheros`).

Вы хотите узнать, **как установить драйвер** для конкретной модели адаптера или **как подключиться** к сети через консоль?

\1. Проверьте, загружена ли прошивка сейчас

Выполните команду:

Если вы видите строки со словами **"failed to load"** или **"Direct firmware load for ... failed"**, значит, драйверу не хватает файлов прошивки.

\2. Подключите репозиторий non-free

В Debian компоненты для таких адаптеров находятся в разделе `non-free-firmware` (для Debian 12) или `non-free` (для старых версий).

1. Откройте список источников:
   `sudo nano /etc/apt/sources.list`
2. Убедитесь, что в конце строк с адресами репозиториев (например, `deb http://debian.org bookworm main`) через пробел добавлены:
   `non-free-firmware non-free`
3. Сохраните (Ctrl+O, Enter) и выйдете (Ctrl+X).

\3. Установите прошивку

Обновите список пакетов и установите нужный драйвер:

```
sudo apt update
sudo apt install firmware-atheros
```

\4. Перезагрузите модуль или систему

Самый надежный способ — перезагрузиться. Либо можно попробовать перезагрузить модуль ядра вручную:

```
sudo modprobe -r ath10k_pci
sudo modprobe ath10k_pci
```

Для кастомной сборки (например, на базе **Debian Trixie/Sid**) вам нужно внедрить пакет прошивки на этапе создания образа или в уже  работающую систему. В Debian 13 (Trixie) структура репозиториев такая  же, как в 12-й — используется ветка `non-free-firmware`.

Вот как это сделать правильно:

\1. Добавление репозитория в конфигурацию

В Debian 13 убедитесь, что в `/etc/apt/sources.list` или в конфигурационных файлах вашего билдера (например, `live-build` или `mmdebstrap`) прописаны правильные ветки:

```
deb http://debian.org trixie main non-free-firmware non-free
```

\2. Если вы используете Live-Build

Если вы собираете ISO-образ через **live-build**, добавьте пакет в список устанавливаемых:

1. Создайте файл (если его нет): `config/package-lists/firmware.list.chroot`

2. Впишите туда одну строку:

   ```
   firmware-atheros
   ```

Убедитесь, что в `config/common` или через параметры `lb config` включены компоненты:

```
lb config --archive-areas "main non-free-firmware non-free"
```

\3. Если вы собираете образ через `debootstrap` / `mmdebstrap`

При создании базовой системы добавьте компоненты и пакет сразу в команду:

```
mmdebstrap --components="main,non-free-firmware,non-free" --include=firmware-atheros trixie /путь/к/папке
```

\4. Включение в "живую" систему (если сборка уже установлена)

Если вы хотите просто "доукомплектовать" уже имеющуюся кастомную ОС, чтобы потом сделать из неё бэкап/образ:

```
sudo apt update
sudo apt install firmware-atheros
# Важно: обновите initramfs, чтобы прошивка подхватилась при загрузке
sudo update-initramfs -u
```



Почему это критично для QCA9377?

Этот чип (ath10k) требует загрузки прошивки **в момент инициализации ядра**. Если вы просто положите файлы в папку, но не обновите `initramfs`, драйвер может снова выдать ошибку при следующей загрузке.

Для того чтобы Wi-Fi (и драйверы в целом) автоматически подхватывались на любом другом компьютере при использовании **live-build**, вам нужно сделать две вещи: включить нужные пакеты прошивок в сборку и разрешить их использование на уровне конфигурации.

Вот пошаговый алгоритм для вашего проекта:

\1. Включите поддержку Non-Free компонентов

В каталоге вашей сборки (там, где вы запускаете `lb config`) нужно указать, что система имеет право скачивать несвободное ПО. Выполните команду:

```

```

*Это добавит необходимые секции репозиториев для поиска драйверов Atheros, Intel, Realtek и др.*

\2. Создайте список пакетов прошивок

Чтобы Wi-Fi работал на «любом другом ПК», лучше добавить не только ваш `firmware-atheros`, но и стандартный набор популярных драйверов.

Создайте файл: `config/package-lists/my-firmware.list.chroot`
И впишите туда:

```
firmware-linux-free
firmware-linux-nonfree
firmware-atheros
firmware-iwlwifi
firmware-realtek
```

*Этот набор покроет 90% сетевых адаптеров (Qualcomm/Atheros, Intel, Realtek).*

\3. Настройте аппаратное обнаружение

Для корректной работы на разном «железе» убедитесь, что в списке пакетов (`config/package-lists/`) у вас присутствуют:

- `pciutils` (для lspci)
- `usbutils` (для lsusb)
- `network-manager` (самый простой способ автонастройки сети на разных ПК)

\4. Автоматическая загрузка (Важно!)

Чтобы ядро гарантированно видело прошивки при загрузке с флешки на новом ПК, проверьте файл `config/common`. В нем должна быть активна опция:

```

```

Теперь очистите старые кэши и соберите образ заново:

```

```

##### Еще у меня в панели задачь значек громкость пишет: Потеряно подключение к службе записи и воспроизведения звука



В KDE Plasma в Debian 13 (Trixie) эта ошибка обычно означает, что звуковой сервер (**PipeWire** или **PulseAudio**) не запущен или конфликтует с конфигурацией вашей кастомной сборки.

Для Debian 13 стандартом является **PipeWire**. Чтобы звук работал «из коробки» на любом железе в вашей сборке, сделайте следующее:

\1. Добавьте необходимые пакеты в сборку

В ваш список пакетов (`config/package-lists/`) добавьте эти строки:

```
pipewire
pipewire-audio
pipewire-pulse
pipewire-alsa
wireplumber
libspa-0.2-bluetooth
plasma-pa
```



- `plasma-pa` — это сам графический апплет громкости для KDE.
- `wireplumber` — критически важный менеджер сессий, без которого PipeWire не будет работать.

\2. Убедитесь в отсутствии PulseAudio

Если в сборку попал классический `pulseaudio`, он может конфликтовать с PipeWire. В Debian 13 лучше полностью перейти на PipeWire. Если вы используете `live-build`, убедитесь, что пакет `pulseaudio` **не** стоит в списке установленных.

\3. Настройка автозапуска (Важно для Live-систем)

Иногда в кастомных сборках сервисы PipeWire не активируются сами. Чтобы они  запускались при старте KDE, убедитесь, что в системе включены  пользовательские юниты (это произойдет автоматически при установке  пакетов выше), но вы можете перестраховаться.

В скрипт послеустановочной настройки (hooks) или при первой загрузке должны выполниться команды от имени пользователя:

```
systemctl --user enable pipewire pipewire-pulse wireplumber
```

\4. Проверьте прошивки для звука

Как и в случае с Wi-Fi, звуковые карты (особенно встроенные в современные ноутбуки Intel/AMD) требуют прошивок.
Добавьте в ваш список прошивок:

```
firmware-sof-signed
firmware-linux-nonfree
```

Без `firmware-sof-signed` на большинстве новых ноутбуков звук не определится вовсе.

Ваш текущий образ, скорее всего, установил KDE, но не установил **сессионный менеджер звука** (`wireplumber`) или пакет-прослойку `pipewire-pulse`, которая имитирует работу PulseAudio для апплетов KDE.

##### Как отключить блокировку экрана и переход в ждущий режим в сборке



Чтобы полностью отключить спящий режим и блокировку экрана в **KDE Plasma** на уровне вашей сборки (так, чтобы это работало сразу после загрузки на любом ПК), нужно внести изменения в настройки среды через  конфигурационные файлы.

В кастомной сборке это лучше всего делать через создание файлов в директории `config/includes.chroot`.

\1. Отключение блокировки экрана (Screen Locker)

В KDE за это отвечает файл `kscreenlockerrc`. Создайте его по пути:
`/etc/xdg/kscreenlockerrc`

Содержимое файла:

```
[Daemon]
Autolock=false
```

*Это отключит автоматическое появление окна пароля через время.*

\2. Отключение спящего режима и затемнения экрана

Настройки энергосбережения хранятся в файле `powermanagementprofilesrc`.
Создайте файл: `/etc/xdg/powermanagementprofilesrc`

Содержимое файла:

```
[AC][SuspendSession]
idleTime=-1
suspendType=0

[Battery][SuspendSession]
idleTime=-1
suspendType=0

[LowBattery][SuspendSession]
idleTime=-1
suspendType=0
```

*Значение `-1` для `idleTime` полностью отключает переход в ждущий режим по таймеру.*

\3. Отключение сна на уровне системы (systemd)

Если вы хотите гарантировать, что система вообще не сможет уснуть (даже при  закрытии крышки ноутбука), можно «замаскировать» цели systemd. В вашей  сборке (например, через скрипт в `config/hooks/`) выполните:

```
systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
```

*Это радикальный метод: кнопка «Спящий режим» останется, но она не будет работать.*

\4. Настройка для всех пользователей (Skeleton)

В Debian конфигурации из `/etc/xdg/` применяются ко всем новым пользователям (включая стандартного пользователя `user` в Live-режиме). Это самый правильный способ для кастомной сборки.

Итоговый список файлов для вашей сборки:

1. `config/includes.chroot/etc/xdg/kscreenlockerrc` (Блокировка)
2. `config/includes.chroot/etc/xdg/powermanagementprofilesrc` (Энергосбережение)

**Важный совет:** Если вы собираете образ для демонстраций или киоск-режима, проверьте также наличие пакета `x11-xserver-utils` и добавьте в автозапуск команду `xset s off -dpms`, чтобы сам монитор не гас по сигналу видеокарты.

Поскольку в Debian 13 используется новая система управления питанием, добавьте в  вашу сборку «маскировку» сервисов сна. Создайте скрипт-хук (hook) в `config/hooks/live/01-disable-sleep.chroot`:

```
#!/bin/sh
set -e
systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
```

*Не забудьте дать файлу права на исполнение: `chmod +x`.*

\3. Отключение "затухания" экрана (Wayland)

В KDE 6 (Debian 13) за это отвечает сервис `kscreen`. Если вы хотите, чтобы монитор **никогда** не гас (например, для режима мониторинга), добавьте в автозапуск (`config/includes.chroot/etc/xdg/autostart/nosleep.desktop`):

```
[Desktop Entry]
Type=Application
Exec=qdbus org.kde.Solid.PowerManagement /org/kde/Solid/PowerManagement/PolicyAgent/InterruptSession "Custom build - No Sleep"

Name=DisableSleep
```

##### у меня в хост системе есть программа в папке /home/oem/Typora-linux-x64/ как добавить эту папку в папку  /home/user/ сборки



Для того чтобы добавить файлы из вашей хост-системы в образ при сборке через `live-build`, используется механизм **`config/includes.chroot`**. Все, что вы положите в эту папку, будет скопировано в корень будущей системы.

Вот пошаговый план:

\1. Создайте нужную структуру папок в сборке

В директории вашего проекта `live-build` выполните команду:

```
mkdir -p config/includes.chroot/home/user/
```

\2. Скопируйте программу с хоста

Теперь скопируйте папку с программой из вашей текущей системы в дерево сборки:

```
cp -r /home/oem/Typora-linux-x64 config/includes.chroot/home/user/
```

\3. Настройте права доступа (Важный нюанс)

Поскольку вы копируете файлы от своего текущего пользователя (oem), в готовой  сборке владельцем файлов может оказаться пользователь с ID 1000, но если в Live-системе ID пользователя отличается, могут возникнуть проблемы с  запуском.

Чтобы права были правильными (для пользователя `user`), создайте скрипт-хук (hook):
Создайте файл: `config/hooks/live/05-set-user-permissions.chroot`
Содержимое файла:

```
#!/bin/sh
# Меняем владельца папки внутри образа на стандартного live-пользователя
chown -R 1000:1000 /home/user/Typora-linux-x64
```

Сделайте его исполняемым: `chmod +x config/hooks/live/05-set-user-permissions.chroot`

\4. Добавьте зависимости

Typora — это Electron-приложение. Чтобы оно запустилось на «чистом» Debian 13, убедитесь, что в вашем списке пакетов (`config/package-lists/`) есть необходимые библиотеки:

```
libnss3
libatk1.0-0
libatk-bridge2.0-0
libcups2
libdrm2
libgtk-3-0
libgbm1
libasound2
```

\5. Бонус: ярлык в меню KDE

Чтобы программу можно было найти в меню приложений KDE, создайте файл:
`config/includes.chroot/usr/share/applications/typora.desktop`

```
[Desktop Entry]
Name=Typora
Exec=/home/user/Typora-linux-x64/Typora
Icon=/home/user/Typora-linux-x64/resources/assets/icon/icon_512x512.png
Type=Application
Categories=Office;TextEditor;
```

**Обратите внимание:** Если вы планируете запускать эту сборку на разных ПК, путь `/home/user/` сработает только в том случае, если стандартный пользователь в вашей сборке действительно называется `user`.
