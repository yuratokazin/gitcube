Вот 3 способа решить эту проблему:

**1. Сжать или разбить файл (Самый простой способ)**
Если файл — это архив или набор данных, попробуйте заархивировать его с  максимальным сжатием. Если он всё еще слишком велик, разделите его на  части (например, по 20 МБ) с помощью архиватора 7-Zip или WinRAR и загрузите части по отдельности.



**2. Загрузить через консоль Git (до 100 МБ)**
Через браузер файлы ограничены 25 МБ, но через терминал можно загружать файлы весом до 100 МБ. 

1. Установите Git на свой компьютер.

```
sudo apt install git
```

2. Откройте папку с проектом в терминале (Git Bash) и выполните команды: 

```
git add .
git commit -m "Добавление файлов"
git push origin main
```

ошибка

```
oem@lenovo:/media/oem/EED7-FA45/KeePassXC$ git add .
fatal: не найден git репозиторий (или один из его каталогов вплоть до точки монтирования /media/oem)
Останавливаю поиск на границе файловой системы (так как GIT_DISCOVERY_ACROSS_FILESYSTEM не установлен).
```

Эта ошибка возникает потому, что Git не видит директорию `.git` ни в текущей папке `KeePassXC`, ни в родительских каталогах вплоть до корня вашей флешки/диска (`/media/oem`).

Вы можете быстро исправить это и настроить отслеживание, выполнив следующие шаги:

1. **Инициализируйте репозиторий:** Перейдите в нужную папку и создайте там репозиторий с помощью команды `git init`.
2. **Добавьте файлы:** Добавьте файлы в индекс для первого коммита.
3. **Сделайте коммит:** Зафиксируйте изменения.

Для этого выполните команды по очереди:

bash

```
cd /media/oem/EED7-FA45/KeePassXC
git init
git add .
git commit -m "Первый коммит"
git remote remove origin
git remote add origin https://github.com/yuratokazin/gitcube.git
```

**Рекомендация:** Убедитесь, что вы не пытаетесь добавить в Git всю флешку целиком. Лучше всего инициализировать Git строго внутри папки с вашим проектом  (например, в подпапке с исходным кодом KeePassXC), чтобы не захламлять  историю лишними файлами с накопителя.



**3. Использовать Git LFS для файлов больше 100 МБ**
Если ваш файл весит от 100 МБ до нескольких гигабайт, настройте Git LFS для его загрузки: 

1. Скачайте и установите расширение Git LFS.
2. В терминале в папке проекта выполните команду для отслеживания вашего типа файлов, например: 

```
git lfs track "*.zip"
git lfs track "*.AppImage"
```

После этого сделайте обычный `git add`, `git commit` и `git push`.

# Создание флешки-ключа (Passkey) для GitHub 

для Debian и Windows

Суть технологии:

**Passkey (Ключ доступа)** — это беспарольный метод входа. Физическая флешка с зашифрованным файлом базы данных выступает в роли **второго фактора** (предмет, который у вас есть), а Мастер-пароль от этой базы — в роли **первого фактора** (знание, которое есть в голове). Это полностью заменяет обычные пароли и коды из SMS/приложений.

------

### Этап 1. Подготовка и правильная разметка флешки

Чтобы флешка без ошибок открывалась и на вашем **Debian Linux**, и на любой **Windows**, на ней нужно удалить старые скрытые разделы и отформатировать её в современную файловую систему **exFAT**.

1. Вставьте флешку в ПК. Откройте терминал в Debian.

2. Посмотрите имя флешки в системе с помощью команды:

   ```
   lsblk
   ```

   *(В нашем случае флешка определилась как диск `sdc`, а её основной раздел — `sdc1`).*

3. Размонтируйте раздел, чтобы система позволила его изменить:

   ```
   sudo umount /dev/sdc*
   ```

4. Запустите утилиту разметки дисков:

   ```
   sudo fdisk /dev/sdc
   ```

5. Последовательно вводите следующие команды внутри `fdisk` (нажимая **Enter** после каждой):

   - **`o`** — очистить старую разметку и создать чистую таблицу разделов MBR.
   - **`n`** — создать новый раздел. На все подвопросы (тип, номера, сектора) просто нажимайте **Enter** (выберутся параметры по умолчанию на 100% объёма флешки).
   - Если появится вопрос *«Remove signature? [Y]es/[N]o»* — введите **`y`** и нажмите Enter.
   - **`t`** — изменить тип созданного раздела.
   - Введите код **`7`** — это тип `HPFS/NTFS/exFAT`, который «родной» для Windows.
   - **`w`** — записать все изменения на флешку и выйти из программы.

6. Выполните финальное форматирование созданного раздела `/dev/sdc1` в файловую систему exFAT:

   ```
   sudo mkfs.exfat /dev/sdc1
   ```

------

### Этап 2. Подготовка программного комплекса KeePassXC

Чтобы флешка была автономной, мы скачиваем на неё версии программы для двух операционных систем. Они будут работать с одним и тем же файлом базы данных.

1. Откройте флешку в проводнике и создайте в корне папку с именем **`KeePassXC`**.

2. Перейдите в терминале в эту папку:

   ```
   cd /media/oem/EED7-FA45/KeePassXC
   ```

3. Скачайте чистую версию программы для **Linux (Debian)** в формате AppImage:

   ```
   wget https://github.com/keepassxreboot/keepassxc/releases/download/2.7.12/KeePassXC-2.7.12-x86_64.AppImage
   ```

4. Сделайте скачанный файл исполняемым (дайте системе право запускать его):

   ```
   chmod +x KeePassXC-2.7.12-x86_64.AppImage
   ```

5. Скачайте **Portable-версию для Windows** (ZIP-архив):

   ```
   wget https://github.com/keepassxreboot/keepassxc/releases/download/2.7.12/KeePassXC-2.7.12-Win64-LegacyWindows.zip
   ```

6. Распакуйте этот ZIP-архив прямо в эту папку:

   ```
   unzip KeePassXC-2.7.12-Win64-LegacyWindows.zip
   ```

7. Удалите сам ZIP-архив, чтобы он не занимал лишнее место:

   ```
   rm KeePassXC-2.7.12-Win64-LegacyWindows.zip
   ```

------

### Этап 3. Создание зашифрованного хранилища

1. Запустите KeePassXC на Debian:

   ```
   ./KeePassXC-2.7.12-x86_64.AppImage
   ```

2. В окне программы нажмите **«Создать новую базу данных»**.

3. Введите имя базы: **`vault`** (латиницей) и нажмите *«Продолжить»*.

4. Нажмите **«Обзор»** и выберите место сохранения — папку `KeePassXC` на вашей флешке. Файл сохранится под именем **`vault.kdbx`**.

5. Задайте надежный **Мастер-пароль** (введите его дважды). Это единственный пароль, который нужно помнить. Нажмите *«Готово»*. На экране откроется пустое окно с надписью **«Корень»**.

------

### Этап 4. Интеграция программы с браузером Firefox

Чтобы браузер мог передавать электронные ключи внутрь флешки, нужно связать расширение Firefox с запущенной программой.

1. В открытом окне KeePassXC нажмите на иконку **Шестерёнки (Настройки)** вверху.
2. Слева выберите **«Интеграция с браузером»**.
3. Справа поставьте галочки: **«Включить интеграцию с браузером KeePassXC»** и отдельно напротив **«Firefox»**. Нажмите **«ОК»**.
4. В Firefox установите официальное расширение **KeePassXC-Browser** из магазина дополнений.
5. Нажмите на значок расширения (зелёный щит) в правом верхнем углу Firefox и нажмите синюю кнопку **«Подключить»** (Connect).
6. На экране поверх всех окон всплывет окно от программы KeePassXC. В поле «Имя подключения» введите английскими буквами **`flash-key`** и нажмите *«Сохранить и предоставить доступ»*. Значок в Firefox загорится ярко-зелёным.
7. Зайдите в настройки самого расширения (нажмите на значок расширения ![img](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==) иконка шестерёнки ![img](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==) вкладка **«Общие»**).
8. Найдите блок **«Ключи доступа»**:
   - **Поставьте галочку**: *«Включить ключи доступа (Включить поддержку веб-аутентификации)»*.
   - **Снимите галочку**: *«Включить резервный вариант ключей доступа»* (чтобы браузер не перехватывал управление).
   - Нажмите синюю кнопку **«Сохранить»** внизу.

------

### Этап 5. Привязка Passkey на GitHub

1. В Firefox откройте настройки безопасности вашего аккаунта: `https://github.com`. Подтвердите личность (введите код из приложения или почты), если сайт потребует «sudo mode».
2. Прокрутите страницу вниз до блока **Passkeys** и нажмите кнопку **«Add»** (или **«Add a passkey»**).
3. Расширение KeePassXC-Browser мгновенно перехватит этот запрос и выведет окно: *«Вы хотите зарегистрировать ключ доступа для github.com?»*.
4. Нажмите кнопку **«Зарегистрироваться»**. (Если программа предложит создать отдельную группу для ключей доступа — нажмите «Да»).
5. **Важно:** Вернитесь в главное графическое окно программы KeePassXC и нажмите **Ctrl + S** (или на синюю иконку дискеты в левом верхнем углу), чтобы физически записать изменения в файл `vault.kdbx` на флешке.
6. Вернитесь в Firefox на страницу GitHub. В появившемся поле **Passkey nickname** введите имя для вашей флешки, например: **`My USB Drive`**, и нажмите кнопку **«Save»** под ним. На экране появится зелёная надпись *«Successfully added a passkey»*.

### KeePassXC-Browser обнаружил ошибку: Не выполнен обмен ключами.



Эта ошибка означает, что браузер Firefox и программа KeePassXC на флешке видят друг друга, но не могут договориться о шифровании канала связи. Такое часто происходит в Linux, если база данных была закрыта, заблокирована или перезапущена, а расширение в браузере пытается использовать старый «сеансовый» ключ.

Поскольку вся настройка у нас уже полностью готова, эта ошибка лечится буквально в два клика.

Как убрать ошибку обмена ключами:

1. **Разблокируйте базу**: Убедитесь, что окно KeePassXC открыто перед вами на экране и вы ввели свой Мастер-пароль. Программа не должна быть свёрнута.
2. **Переподключите расширение**:
   - В правом верхнем углу Firefox нажмите на значок расширения KeePassXC (зелёный щит).
   - В появившемся маленьком окошке нажмите кнопку **«Переподключить»** (или значок в виде круговых стрелок).
3. **Подтвердите связь**: Программа на флешке снова выбросит окно *«Получен запрос на ассоциацию»*. Введите уже знакомое имя **`flash-key`** и нажмите «ОК». Значок в Firefox мгновенно станет ярко-зелёным.

После этого обновите страницу GitHub клавишей **F5**, и всё снова будет работать идеально!

Удалось **вернуть зелёный цвет значку**, или Firefox наотрез отказывается делать обмен ключами?

### ну как это сделать завтра



Чтобы завтра (или в любой другой день) эта проверка прошла успешно и больше не появлялась, нам нужно один раз сохранить правильный цифровой ключ внутрь вашей флешки.

Поскольку на смартфоне у вас нет приложения с кодами, мы настроим генерацию этих 6-значных кодов **прямо внутри вашей программы KeePassXC на флешке**. Тогда при проверке программа сама будет выдавать нужный код.

Вот подробный план, как мы сделаем это завтра:

### Шаг 1. Откроем настройки на GitHub

1. Вы зайдете на GitHub, и сайт снова покажет это окно проверки.
2. Вместо ввода кода вы нажмете кнопку **«Reconfigure 2FA»** (Перенастроить 2FA) или **«Edit settings»** (Изменить настройки), которая есть в этом тексте.
3. GitHub покажет на экране большой черный квадратный **QR-код**.

### Шаг 2. Запишем секретный ключ на флешку

1. Под QR-кодом на сайте всегда есть текстовая ссылка: *«Can't scan? Copy the text key»* (Не можете отсканировать? Скопируйте текстовый ключ). Вы нажмете на нее и скопируете длинный набор букв и цифр (это секретный ключ TOTP).
2. Откроете KeePassXC на флешке, найдете строчку **GitHub**, нажмете по ней правой кнопкой мыши и выберете пункт **«TOTP»** ![img](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==) **«Настроить TOTP»**.
3. Вставите туда скопированный ключ и нажмете «ОК».
4. Обязательно сохраните базу данных кнопкой **Ctrl + S**.

### Шаг 3. Успешная проверка

После этого в KeePassXC рядом со строчкой GitHub начнут автоматически появляться те самые 6-значные коды, которые меняются каждые 30 секунд. Вы просто перепишете текущий код на сайт, GitHub увидит, что всё настроено правильно, и эта проверка исчезнет навсегда.

Завтра, **если, появилтся снова это окно проверки на GitHub**, мы настроим всё по шагам изложенным выше.
