## Добавьте пользователя user в группу sudo

````
user@debian:~$ sudo nano /etc/apt/sources.list
[sudo] пароль для user:
user is not in the sudoers file.
````

Вы столкнулись с ошибкой: пользователь user не имеет прав sudo, поэтому не может редактировать системные файлы (в частности, /etc/apt/sources.list).

#### Как решить проблему

Добавить пользователя в группу sudo (требуется доступ к root)

Если у вас есть пароль root:

Войдите как root (su -).

Добавьте пользователя user в группу sudo:

    usermod -aG sudo user

Выйдите из root (exit) и заново войдите в систему (или перезапустите сеанс).

Теперь команда sudo должна работать.

#### Синтаксис sources.list.

При редактировании следите за правильностью строк (пример для Debian 12 Bookworm):

    #deb cdrom:[Debian GNU/Linux 12.7.0 _Bookworm_ - Official amd64 DVD Binary-1 with firmware 20240831-10:40]/ bookworm main
    
    deb http://deb.debian.org/debian bookworm main contrib non-free
    deb-src http://deb.debian.org/debian bookworm main contrib non-free
    
    Для постоянного использования репозиториев лучше подключить сетевые источники (например, deb https://deb.debian.org/debian bookworm main).

#### Проверка после правки

Обновите список пакетов:

    sudo apt update

Убедитесь, что ошибок нет.

### Автоматический вход в KDE Plasma на Debian 12

Чтобы настроить автоматический вход в KDE Plasma на Debian 12 без ввода  пароля, необходимо изменить настройки дисплейного менеджера SDDM. 

Вот  пошаговая инструкция:

**Откройте терминал** и выполните команду для редактирования конфигурационного файла SDDM:

```bash
sudo nano /etc/sddm.conf.d/kde_settings.conf
```

Если папка `/etc/sddm.conf.d/` не существует, создайте её командой:

```bash
sudo mkdir -p /etc/sddm.conf.d/
```

**Добавьте в файл следующие строки**:

```ini
[Autologin]
Session=plasma
User=ваше_имя_пользователя
```

Замените `ваше_имя_пользователя` на фактическое имя вашего пользователя. Параметр `Session` можно оставить как `plasma` для KDE Plasma, но если требуется другая сессия, узнайте её название командой `echo

### Запретить блокировку экрана и переход в ждущий режим

Содержание файла /home/user/.config/kscreenlockerrc                                    

````
[$Version]
update_info=kscreenlocker.upd:0.1-autolock

[Daemon]
LockOnResume=false
Timeout=45 
````

как можно его изменить чтобы он запретил блокировку экрана и переход в ждущий режим

Чтобы **полностью отключить блокировку экрана** в KDE Plasma через файл `kscreenlockerrc`, нужно изменить параметр `Timeout`. Для **отключения перехода в ждущий режим** потребуются дополнительные настройки вне этого файла.

### Изменение kscreenlockerrc (отключение блокировки экрана)

Откройте файл в текстовом редакторе:

```bash
nano ~/.config/kscreenlockerrc
```

Измените значение `Timeout` на `0` (отключает таймаут):

```ini
[$Version]
update_info=kscreenlocker.upd:0.1-autolock

[Daemon]
LockOnResume=false
Timeout=0
```

**Объяснение параметров:**

- `Timeout=0` — полностью отключает автоматическую блокировку экрана по таймеру;
- `LockOnResume=false` — уже стоит верное значение (экран не блокируется после выхода из сна).

После сохранения файла:

1. Перезапустите сеанс (выйдите и войдите в учётную запись) **или**
2. Примените изменения командой:

```bash
qdbus org.kde.ksmserver /KSMServer reconfigure
```

### Отключение перехода в ждущий режим (сна)

Файл `kscreenlockerrc` **не управляет** переходом в ждущий режим. Для этого нужны отдельные настройки.

#### Вариант 1. Через системные настройки (GUI)

1. Откройте **«Системные настройки»** → **«Энергосбережение»**.
2. В разделе **«Спящий режим»**:
   - Установите **«Никогда»** для «Переход в спящий режим при бездействии»;
   - Отключите «Автоматически переходить в спящий режим».
3. В разделе **«Экран»**:
   - Установите **«Никогда»** для отключения экрана.
4. Нажмите **«Применить»**.

#### Вариант 2. Через конфигурационные файлы

**1. Отключение сна через systemd**
Создайте файл:

```bash
sudo nano /etc/systemd/sleep.conf.d/disable-suspend.conf
```

Добавьте:

```ini
[Sleep]
AllowSuspend=no
AllowHibernation=no
AllowSuspendThenHibernate=no
AllowHybridSleep=no
```

Перезапустите сервис:

```bash
sudo systemctl restart systemd-logind.service
```

**2. Отключение реакции на закрытие крышки**
Отредактируйте:

```bash
sudo nano /etc/systemd/logind.conf
```

Добавьте/измените:

```ini
HandleLidSwitch=ignore
HandleLidSwitchDocked=ignore
```

Перезапустите сервис:

```bash
sudo systemctl restart systemd-logind.service
```

### Проверка текущих настроек

Убедитесь, что блокировка отключена:

```bash
cat ~/.config/kscreenlockerrc | grep Timeout
# Должно вывести: Timeout=0
```

Проверьте статус сна:

```bash
systemctl status sleep.target
```

### Итоговые действия

1. Измените `Timeout=0` в `kscreenlockerrc`.
2. Настройте энергосбережение через GUI **или** отредактируйте файлы systemd.
3. Перезапустите сеанс или соответствующие сервисы.
4. Проверьте, что экран не блокируется и система не уходит в сон.

# KDE Plasma перезапустить рабочий стол 

Если рабочий стол KDE в Debian перестал работать после сбоя, можно  попробовать несколько способов восстановления. Выбор метода зависит от  характера проблемы и доступных возможностей.

## Перезапуск plasmashell

В современных версиях KDE Plasma можно перезапустить рабочий стол без перезагрузки системы. Для этого выполните следующие шаги:

1. Откройте терминал (например, с помощью комбинации клавиш `Alt+F2`).
2. Введите команду `killall plasmashell`, чтобы завершить процесс, управляющий рабочим столом.
3. Затем запустите `kstart5 plasmashell`, чтобы перезапустить plasmashell. maketecheasier.com +1

Если используется KDE 4, замените `plasmashell` на `plasma-desktop`. 

## Перезапуск диспетчера дисплеев

Если перезапуск plasmashell не помог, можно попробовать перезапустить диспетчер дисплеев (например, `systemd-logind` или `lightdm`). Для этого в терминале выполните команду:

```
bash
sudo systemctl restart systemd-logind
```

или

```
bash
sudo systemctl restart lightdm
```

После этого потребуется заново войти в систему. 

## Удаление проблемных конфигурационных файлов

Иногда сбой может быть вызван повреждёнными настройками. В этом  случае можно попробовать удалить или переименовать каталоги с  конфигурацией KDE:

- `~/.kde`;
- `~/.kde4` (если используется старая версия);
- `~/.config/kde`.

Перед удалением сделайте резервную копию важных данных. После  удаления каталогов при следующем входе в систему KDE создаст новые  конфигурационные файлы по умолчанию. unix.stackexchange.com +1

## Проверка файла `.xsession-errors`

Файл `.xsession-errors` в домашнем каталоге содержит  логи ошибок при запуске сессии. Анализ этого файла может помочь выявить  причину сбоя. Проверьте его содержимое на наличие сообщений об ошибках  или подозрительных записей. superuser.com +1

## Переустановка KDE

Если другие методы не помогли, можно попробовать переустановить KDE. Для этого выполните:

1. Удалите пакеты KDE с помощью 

   ```
   apt
   ```

   :

   ```
   bash
   ```

```bash
sudo apt remove kde*
```

Очистите зависимости:

```
bash
sudo apt autoremove
```

Установите KDE заново:

```
bash
```

1. ```bash
   sudo apt install kde-plasma-desktop
   ```

## Дополнительные рекомендации

- **Обновление системы.** Убедитесь, что система обновлена до последней версии: `sudo apt update && sudo apt upgrade`. Устаревшие пакеты могут вызывать конфликты.
- **Проверка журналов системы.** Посмотрите логи в `/var/log/` (например, `syslog` или `kern.log`) — там могут быть дополнительные сведения о сбое.
- **Восстановление из резервной копии.** Если ранее была создана резервная копия настроек KDE, попробуйте восстановить её.

Если проблема сохраняется, уточните детали: например, какие именно  симптомы сбоя наблюдаются (зависание, отсутствие иконок, ошибки на  экране и т. д.). Это поможет дать более точный совет.

Если после закрытия терминала пропал графический интерфейс KDE (рабочий стол, панель, виджеты), скорее всего, процесс `plasmashell` завершился. Это нередко случается при некорректном завершении терминала или конфликте процессов.

## Что делать прямо сейчас

### Шаг 1. Перезапустить plasmashell через консоль

1. Нажмите `Ctrl + Alt + F2` (или `F3`–`F6`) — вы перейдёте в текстовую консоль.

2. Войдите в систему: введите логин и пароль.

3. Выполните команды:

   bash

1. ```bash
   killall plasmashell 2>/dev/null || true
   kstart5 plasmashell
   ```

2. Переключитесь обратно в графический режим:
   `Ctrl + Alt + F7` (для X11)
   или
   `Ctrl + Alt + F1`/`F2` (для Wayland).

### Шаг 2. Если plasmashell не запускается

Проверьте, работает ли графическая среда:

bash

```bash
ps aux | grep -i plasma
```

Если процессов нет, попробуйте:

bash

```bash
dbus-launch kstart5 plasmashell
```

### Шаг 3. Перезапуск графического сервера (если ничего не помогло)

**Для X11 (SDDM/KDM):**

bash

```bash
sudo systemctl restart sddm
```

**Для Wayland (если используется):**

bash

```bash
sudo systemctl restart display-manager
```

После этого вы попадёте на экран входа — войдите снова.

## Почему это происходит

Частые причины:

- **Некорректное завершение терминала** — если закрыть терминал с запущенным `plasmashell`, иногда процесс завершается аварийно.
- **Конфликт плагинов** — ошибки вроде `webarchivethumbnail.so` могут приводить к падению.
- **Проблемы с правами** — если терминал запущен от root, а plasmashell от пользователя, возможны конфликты.

## Профилактика на будущее

1. **Запускайте plasmashell правильно:**

   bash

```bash
kstart5 plasmashell &
```

Символ `&` отправляет процесс в фоновый режим — можно закрывать терминал без риска.

**Используйте альтернативные способы перезапуска:**

- Через меню KDE: `Alt + F2` → введите `plasmashell --replace` → Enter.
- Через системный монитор: завершите `plasmashell` и запустите заново.

**Проверьте логи на ошибки:**

bash

```bash
grep -i error ~/.xsession-errors
journalctl -b -0 | grep -i plasma
```

**Обновите систему:**

bash

1. ```bash
   sudo apt update && sudo apt upgrade
   ```

## Если проблема повторяется регулярно

1. **Создайте резервную копию настроек:**

   bash

```bash
cp -r ~/.config/plasma-desktop-appletsrc ~/plasma-backup
```

**Сбросьте настройки Plasma:**

bash

1. ```bash
   rm -rf ~/.config/plasma-* ~/.cache/plasma*
   ```

   После этого перезайдите в систему — KDE создаст конфигурации по умолчанию.

2. **Проверьте установленные виджеты** — удалите сторонние или устаревшие.

Если после всех шагов проблема сохраняется, укажите:

- версию KDE (`plasmashell --version`);
- тип графического сервера (X11 или Wayland);
- какие виджеты/темы установлены.
